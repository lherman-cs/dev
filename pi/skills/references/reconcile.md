# Reconcile before acting

Work from observable state, even with no prior session. Identify the current request, repository and worktree, applicable approved artifacts if any, Git history/status/diff (including untracked files), relevant conventions, and live remote evidence. Derive the remaining outcomes and proof from these sources. A spec, plan, progress file, transcript, worker result, or earlier phase is not a prerequisite to begin; existing artifacts constrain work only when their applicability and authority can be established. Do not treat an artifact's status marker alone as approval. Resolve ordinary choices from the request and evidence; ask only when consequential product semantics, scope, ownership, or authority cannot safely be determined.

Own this worktree exclusively. Classify pre-existing tracked and untracked changes by content before staging or removal. Adopt relevant changes under the same scope and proof as new work. Preserve unresolved relevant conflicts. For irrelevant edits, attempt a recoverable local backup outside the worktree, then remove only classified paths; report paths removed and backup location or failure. Backup is best-effort, not a veto, and may be unverified. Never sweep ignored files, rewrite committed history, overwrite independent remote work, or depend on another agent to return. Other agents can provide read-only evidence from independent worktrees, not write into this one.

Verify uncertain side effects before retrying. Reobserve commits, checks, remote writes, and candidate identity after interruption, cancellation, or failed delivery; stale results are leads, not proof. Repair and retry ordinary failures while making progress. On repeated nonproductive failure, diagnose the concrete obstacle and change approach rather than looping. Only an unresolved consequential decision or unavailable required authority/evidence warrants a pause; state exactly what is missing and resume through this same workflow.
