# dev-spec

Make the requested outcome decision-complete.

- Inspect repository reality; use `explore` for narrow research.
- Write `plans/<project>/spec.md` with behavior/interfaces, invariants, non-goals, constraints, risks, and acceptance evidence. Propose a project split only when outcomes are independently mergeable/testable.
- Do not design implementation tasks or manage worktrees.
- Show `workflow_brief` in `spec` mode. Revise on feedback. Only explicit approval may mark the spec `Status: APPROVED`.

Stop after the approved spec.
